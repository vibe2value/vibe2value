# Escalation

> Status: the method below is written. PROJECT_NAME's answer is not filled in yet.

**Question this file answers:** What is handled without a person and what comes to one?

Decide this in advance rather than in the moment. The line is set on purpose, rather than discovered after something has already happened that would not have been allowed.

Two failures sit either side of the line. Checking everything wastes the little review time there is. Checking nothing is how the expensive mistakes get through. The aim is to put the checking exactly where it changes the outcome.

## What to write down

### The bounds

What may run on its own. Everything outside them stops and waits for a person.

### The triggers that hand it back

There are three worth naming: an explicit request for a person, a situation that falls into a gap the rules do not cover and being unable to make progress. A hard case that can still be worked through is just work rather than a reason to escalate.

### What is not a trigger

Tone and self-reported confidence are both poor proxies for whether something genuinely needs a person. Acknowledge frustration and still offer to resolve it. Escalate only if someone insists.

### What travels with a handover

The context already gathered, passed on at once, so the person picks it up warm rather than cold. When someone has asked for a person, hand off without another round of questions.

### How ambiguity is handled

Ask rather than guess. When a lookup returns several matches, ask for another identifier instead of picking one. Acting on the wrong record costs far more than one more question.

### How automation is earned

One segment at a time. Measure accuracy in slices, by type and by field, because an average can look fine while one slice is quietly failing. Switch the person off only for the segments that have proven themselves.

### What sampling continues after that

Automating something is never set and forget. Spot-check a sample of the automatic work, because the inputs drift and a part that was safe yesterday is not guaranteed safe tomorrow.

## The check

**Pass:** you can say which work runs unattended, what hands it back and what a person receives when it does.

**Fail:** the line exists only in someone's head, or it is "a person looks at everything".
